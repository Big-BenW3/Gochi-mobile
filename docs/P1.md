## 2. Environment

Everything lives in one `.env` at the repo root. Both the app and the API read
it, which is why it is not inside `mobile/`.

| Variable                        | Read by       | Shipped in the APK?                    |
| ------------------------------- | ------------- | -------------------------------------- |
| `EXPO_PUBLIC_PRIVY_APP_ID`      | app           | yes (fine — it is a public identifier) |
| `EXPO_PUBLIC_PRIVY_CLIENT_ID`   | app           | yes (fine)                             |
| `EXPO_PUBLIC_API_URL`           | app           | yes (fine)                             |
| `EXPO_PRIVATE_PRIVY_APP_SECRET` | **API only**  | **no**                                 |
| `DATABASE_URL`                  | API           | no                                     |
| `DATABASE_URL_POOLED`           | API           | no                                     |
| `API_JWT_SECRET`                | API           | no                                     |
| `HELIUS_API_KEY`                | API (from P7) | no                                     |
| `PAYER_KEYPAIR_PATH`            | API (from P4) | no                                     |
| `SOLANA_RPC_URL`                | API           | no                                     |

**The one rule that matters:** anything prefixed `EXPO_PUBLIC_` is inlined into
the app bundle at build time and is readable by anyone who unpacks the APK. A
server secret must never carry that prefix. The API refuses to start if it finds
one, which is a deliberate tripwire — see `apps/api/src/env.ts`.

### Generate the session signing secret

```bash
openssl rand -base64 48
```

Paste the output into `API_JWT_SECRET=`. Rotating this invalidates every issued
session token, which is the correct behaviour if you ever suspect it leaked.

### Check the API can start

```bash
npx tsx apps/api/src/index.ts
```

Right now this prints a "no server yet" message and exits, because the service
lands in P3. That is expected. What it proves is that the env loader found every
required variable. If a secret is missing you get a named list instead of a 500
later.

## 3. Android build

`mobile/android/` is **generated**, gitignored, and safe to delete at any time.
It is regenerated from `app.json` by prebuild, so `app.json` is the only source
of truth for the package id.

```bash
cd /home/bigben/projects/Seeker/SLS/mobile

# Only needed after changing app.json (name, icon, package id, plugins).
npx expo prebuild -p android --clean --no-install

# Build the debug APK.
cd android && ./gradlew assembleDebug

# Install it on the connected phone.
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The APK lands at
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`.

> This is a **development build**, not Expo Go. `@wallet-ui/react-native-kit`
> and `react-native-quick-crypto` need a native runtime, and Expo Go cannot
> load them. There is no way around this for MWA.

### First-build time

10–20 minutes for the Gradle daemon, NDK and CMake to warm up. Every build after
that is roughly a minute. Do not kill it partway — the caches are the point.

## 4. Run it

Two processes, two terminals.

**Terminal 1 — Metro, the JS bundler:**

```bash
cd /home/bigben/projects/Seeker/SLS
npm run start
```

Wait for `Waiting on http://localhost:8081`.

**Terminal 2 — the API (once P3 lands; harmless before then):**

```bash
cd /home/bigben/projects/Seeker/SLS
npm run api
```

**On the phone:** open Gochi. A debug build talks to Metro over the network, so
the handset must reach this machine's port 8081.

If it cannot find the bundler, forward the port over USB instead — this is the
usual fix for a phone on a different wifi network:

```bash
adb reverse tcp:8081 tcp:8081
```

## 5. Verifying on your phone

You can do this yourself at the end of the phase. With Metro up and the APK
installed, walk the P1 screens:

| Screen  | What it is                | What to check                                                  |
| ------- | ------------------------- | -------------------------------------------------------------- |
| **A04** | Authentication            | Wallet connect button appears; connects to Phantom or Solflare |
| **A05** | Seeker connection loading | Appears while the wallet handshake resolves                    |
| **A06** | Privy Google auth         | Privy modal opens, Google sign-in completes                    |
| **A07** | Link Seeker wallet        | Wallet links to the Privy account                              |
| **A08** | Genesis verified          | Only if the wallet actually holds an SGT                       |
| **A09** | Genesis not detected      | The expected result for an ordinary wallet                     |

**A09 is the correct outcome for you.** Genesis verification is honest by
design: a wallet with no Seeker Genesis Token shows "not detected". The app must
never claim ownership it cannot prove. Both wallet paths (SIWS and Privy) should
work on your phone, so test whichever is convenient — but test that a wallet
which _is_ not a Seeker lands on A09, because that is the security property that
matters.

### If MWA misbehaves

The old README suggests `adb shell locksettings set-pin 1234` plus a restart of
`com.solana.mwallet`. That is a **Mock MWA** workaround and you do not need it —
you have real wallets installed (Phantom `app.phantom`, Solflare
`com.solflare.mobile`). Ignore that step.

### Capture a bug

```bash
adb logcat -c && adb logcat | grep -iE "gochi|privy|wallet|react"
```

`-c` clears the buffer first so you only see what happens after you hit the
broken screen.

## 7. Troubleshooting

| Symptom                                   | Cause                                | Fix                                                                                        |
| ----------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------ |
| Metro unreachable from phone              | Different network                    | `adb reverse tcp:8081 tcp:8081`                                                            |
| App installs then shows a red screen      | Native module missing from the build | Rebuild the APK; a JS reload cannot fix native code                                        |
| Gradle `SDK location not found`           | `ANDROID_HOME` unset                 | `export ANDROID_HOME=$HOME/Android/Sdk`                                                    |
| Gradle out of memory                      | Daemon heap too small                | `org.gradle.jvmargs=-Xmx2048m` is already set in `gradle.properties`                       |
| Privy rejects every SIWS attempt          | SVM (Solana) wallets toggle is off   | Enable it in the Privy dashboard under User management → Authentication → External wallets |
| Privy rejects the calling app             | Client identifier mismatch           | `App settings → Clients` must read exactly `com.gochi.app`                                 |
| `adb devices` shows nothing               | Not authorised                       | Unplug/replug, accept the RSA prompt on the handset                                        |
| Wrong package id after editing `app.json` | `android/` is stale                  | `npx expo prebuild -p android --clean --no-install`                                        |
